# AGENT_05 ｜ Vibecoding 需求包（首轮描述稿 + 迭代提示词序列）

执行者：AI 起草，H1+H2 双人评审 ｜ 时间窗：7.15–7.23（依赖 01–04 中期产出）｜ 下游：7.24 起平台搭建的唯一驾驶手册

## 1｜第一性原理
F2：在抖音AI平台上，**提示词就是源代码**。首轮描述稿决定 AI 对产品的"第一印象"，返工成本随轮次指数上升；迭代序列决定 40 小时+一周里每一轮对话的产出密度。F5：两个人没有试错余量——每一轮提示词都要在开口前就知道"这轮要验收什么"。

## 2｜上下文胶囊
平台流程（章程）：小程序 Tab 入口 → 对话描述需求 → 选"自定义 feed 卡（AI内容卡）" → AI 生成 → Web/真机扫码预览 → 持续对话调优；扩展机制：Skills（如 frontend-design）/工具/生成式模型(@豆包)/知识库/数据库表(JSON 导入)/Figma 导入。产品定义与 tokens 见 AGENT_00 §2。

## 3｜目标（Goal）
产出可直接粘贴的《首轮需求描述稿》v1 + 13 轮迭代提示词序列（每轮含目的/提示词要点/验收标准），全包经双人评审通过、歧义清零。

## 4｜输入
AGENT_01 schema 摘要、AGENT_02 表结构与评分说明、AGENT_03 两组样例、AGENT_04 tokens/first5s/page_specs。

## 5｜交付物

### 5.1 `first_prompt.v1.md` —— 首轮描述稿（以下为 v0.9 草稿，⚠️ 处待 AGENT_06 测绘后定稿）

> 我要做一个名为「追·光」的作品：一张抖音 feed 内容卡（自定义 feed 卡／AI内容卡）+ 点击进入的小程序。
>
> **一句话**：让用户在刷到的一瞬间知道"今晚值不值得为天空出门"，并给出立刻可执行的出门与拍摄路径。
> **目标人群与刷到时刻**：25–35 岁城市手机摄影与生活记录爱好者；工作日 16:00–19:00 刷抖音的间隙——正是决定"今晚出不出门"的时刻。
>
> **Feed 卡（信息流中的样子）**：背景为随当前时刻变化的天空渐变（色卡锚点 #3a4a6b→#e0a060→#c84858→#5a3870），下沿城市剪影；主信息为今晚晚霞评分（0–100 大数字）+ 等级标签（值得跑出门／顺路看看／今天歇着）；副信息为峰值时刻、距峰值倒计时、一句 AI 行动文案（如"往西走，深圳湾还来得及"）。点击进入小程序。**前 5 秒要求：0.5 秒评分可读，1.5 秒看懂值不值得，3 秒想点。**
>
> **小程序四页**：
> P1 封面详情：评分+峰值+今日光线时刻轴；核心互动是一根可拖动时间条，拖动时背景颜色沿色卡连续变化并显示对应时刻与光况。⚠️(拖动不可行则退：点按分段切换)
> P2 轻导航：当前位置→推荐机位的步行路线视图，顶部倒计时"距峰值 XX 分钟"，底部结论句"步行 12 分钟 · 18:31 到达 · 正好赶上"。⚠️(定位与地图能力待测)
> P3 机位攻略：样张大图（含作者署名）、站位描述、朝向罗盘（指示拍摄方向 265°）、最后 100 米图文步导（3–5 步）、底部横滑样张参考流；本页角落悬浮小地图窗。⚠️(悬浮窗不可行则退：顶部收起式地图条)
> P4 快拍：构图模板线示意（三分/引导线可切换）、3 个滤镜预设切换预览、AI 一句话拍摄建议、按钮"拍好了，去发布"引导带话题发布。
>
> **数据**（我将以 JSON 导入数据库表，先按此建表）：`spots`(id/name/scene/lat/lng/stand_desc/bearing/best_window/focal/compose_template/filters/sample_img/sample_credit/walk_steps/copy_slots)；`sun_events`(spot_id/date/sunset/golden_start/golden_end/blue_start/blue_end/azimuth_10min)；`weather_daily`(date/city/cloud_low/cloud_mid/cloud_high/humidity/visibility/code/updated_at)；`copy_samples`(input_json/output_text)。评分由 sun_events+weather_daily 按我提供的公式计算，feed 卡与 P1 显示同一评分。
>
> **AI 能力**：行动文案与拍摄建议调用生成式模型（@豆包），我提供系统提示词与 few-shot（copy_samples 表）；硬约束：行动句 ≤26 字、建议 3 条各 ≤15 字、只能引用 spots 表中真实机位名。
>
> **边界状态**：评分 <45 → 劝退文案+明日预告；雨天 → "今晚看雨，明晚有戏"；21:00 后刷到 → 明日预告版卡面。
> **视觉基调**：深色底、克制、发光感；主色 #ff8a3d；中文无衬线为主。
> **本轮只要**：feed 卡 + 四页骨架 + 假数据跑通，我确认结构后再逐页调优。

### 5.2 `iteration_playbook.md` —— 13 轮迭代序列（每轮 = 目的／提示词要点／验收）
R1 骨架确认 → R2 数据库建表与 JSON 导入（真数据替换假数据）→ R3 feed 卡视觉与前5秒时序（对照 first5s_spec 逐条报验）→ R4 P1 时间条互动（或降级形态）→ R5 P2 导航（按测绘选型）→ R6 P3 攻略页字段绑定 → R7 悬浮窗/罗盘（或降级形态）→ R8 P4 快拍三件套 → R9 @豆包接入与样例挂载 → R10 边界四态 → R11 真机扫码走查修缺陷 → R12 质感冲刺（调用 frontend-design skill，对照 tokens 表逐项）→ R13 发布预检（名称/图标/应用场景[抖音Feed+侧边栏搜索]/运营人信息 核对清单）。
每轮模板：`【目的】…【给平台的话】…【验收（二元）】…【若失败的降级话术】…`

## 6｜交付条件（DoD）
- C1 首轮稿朗读测试通过：两人各朗读一遍，无一处需要口头补充解释。
- C2 歧义清零：另派一个"敌对 agent"专门找歧义，找出的 ≥5 处全部修复并留修订记录。
- C3 13 轮每轮的验收标准均可二元判定，且 R3/R4/R6 的验收直接引用 AGENT_04 文档条目编号。
- C4 ⚠️ 占位项 ≤4 个且每个都在 AGENT_06 十二问中有对应测试项。
- C5 数据段与 AGENT_01/02/03 最终 schema 字段级一致（diff 为空）。

## 7｜检查任务
- K1 敌对歧义审查报告（找到什么、怎么改）存档。
- K2 schema 一致性 diff 输出粘贴。
- K3 用 R1+R2 两轮对一个通用对话模型做"沙盘推演"（假装它是平台），看它复述出的产品结构是否正确，偏差点回写进首轮稿。
- K4 发布预检清单与章程提交要求逐条对照（名称/图标/应用场景/运营人信息/链接入飞书表格），无遗漏。
- K5 字数与信息密度检查：首轮稿 ≤900 字（超出则拆进 R 轮，首轮只留骨架必需信息）。

## 8｜禁区与红线
首轮稿不堆动效细节（那是 R3+ 的事）；任何一轮不同时改两个页面（问题定位会失效）；不在提示词里粘贴受版权保护的他人文案。

## 9｜升级条件
AGENT_06 测绘推翻 ≥2 个 ⚠️ 假设（需求包需人工重排优先级）；平台对首轮稿的结构理解连续两次跑偏（说明描述范式不对，停下重写而非硬调）。
