## 0. 本版修正的五个基石（先读这里，v1 有几处必须纠偏）

重读章程后，以下五点是本蓝图的地基，其中前三点修正了 v1 的判断：

1. **【最重要】大区赛作品必须通过「抖音AI平台」(douyin-ai.bytedance.net) 产出。** 章程明确：赛道三大区赛"需要使用抖音AI平台进行创作，可以使用抖音数据API，作品可以真实进入抖音feed"，形态为**抖音 feed 卡片 + 点击卡片进入的小程序**。这意味着我们的 React 代码库**不再是最终交付物**，而是转化为三种弹药：交互规格说明书、Figma 高保真稿（平台支持 Figma 导入还原）、数据与算法资产。v1 里"迁移 Vite + Vercel 部署"的路线**作废**。
2. **赛道三评审表修正。** 评审锚点："用户在刷到的一瞬间，是否就能被打动、被满足，并自然产生一次互动或使用？"五个维度：场景与问题洞察 20% / AI能力与产品结合 15% / **体验完整性 30%**（是否"刷到即用"、无学习成本、极短时间内完成交互）/ 用户价值感 20% / 创新性与延展潜力 15%（持续更新与复访动机、期待再次刷到）。v1 写的"完成度与技术实现30%"口径作废。**战略含义：卡片的前 5 秒是全场最贵的 5 秒。**
3. **评审形式没有 8 分钟路演。** 现场 Day 3 流程是：12:00 黑客松结束 → 评委线上看提交 → 14:00–17:00 **评委参加游园会**（现场体验作品）→ 选手互评 → 颁奖。所以 v1 的"路演 PPT"变为"**游园会展位与 30 秒话术**"，作品必须自己会说话。

## 1. 北极星与设计原则

**北极星**：一张真实出现在抖音信息流里的卡片，让评委在游园会上掏出自己的手机刷到它的那一瞬间，就被"今晚深圳值不值得出门"打动，并顺手完成一次互动——评委本人就是用户，深圳就是现场。

由评审表反推的四条设计原则，所有 Part 的取舍以此为准绳：

- **前 5 秒原则**（体验完整性 30%）：刷到后 0.5 秒评分可读，1.5 秒看懂"今晚值不值得"，3 秒内产生第一次互动欲望。任何挡在前 5 秒里的东西都砍。
- **AI 可见原则**（AI能力 15%）：AI 不是后台黑盒——评分、行动文案、拍摄建议要让评委"看见 AI 正在为此刻的我判断"。平台的 Skill/知识库/豆包模型机制要显性用上。
- **此刻原则**（场景洞察 20% + 用户价值 20%）：所有内容锚定"现在、这里"——评委在深圳、在当天下午刷到，卡片说的就是当天傍晚的深圳。
- **再刷到原则**（延展潜力 15%）：卡片自带"明天预告"与随时间变化的状态，让人期待下一次遇见——这正是章程赛道描述里点名鼓励的"持续变化的感觉"。

## 3. Part 章程：五个作战单元

三个人，五个 Part——Part 是任务域不是人头，允许一人多戴帽，但每个 Part 有唯一负责人（Owner）对验收标准负责。

| Part | 使命（一句话） | Owner | 主要接口 |
|---|---|---|---|
| **PART-P 平台工程** | 在抖音AI平台上产出真实入 feed 的卡片+小程序，还原原型体验 | A | 消费 X 的规格、D 的数据、C 的素材 |
| **PART-D 数据与光线引擎** | 评分公式、机位库、太阳/天气数据链路、豆包文案能力 | B | 向 P 供数据表/Skill/提示词 |
| **PART-C 内容与授权** | 合法样张与步导素材（授权为主、实拍为辅）+ 用户访谈 | C（授权外联由提出该策略的成员主抓） | 向 P/N 供图，向 N 供语录 |
| **PART-X 体验与动效规格** | React 原型 → Figma 稿 → 平台还原度守门 | A/C 共担，A 拍板 | 向 P 供 Figma+tokens+首5秒规范 |
| **PART-N 叙事与展陈** | 海报、游园会展位、话术、（自选）说明材料 | C 牵头，全员供弹 | 消费所有 Part 的成果 |

**初赛资产 → 平台机制映射表**（这是本次转型的核心工程思想，PART-P 与 PART-D 共同执行）：

| 初赛资产 | 平台机制（章程提及） | 落点 |
|---|---|---|
| 评分公式 / 光线引擎 | 自定义 **Skill** 或 **工具** | 卡片实时评分与"AI 可见" |
| 机位库 JSON | **数据库表**（附件上传导入） | 攻略页数据源 |
| 精修文案库 + LLM 调用 | **生成式模型**（@Doubao 系列）+ few-shot | 行动文案 / 拍摄建议 |
| 摄影方法论 / 步导知识 | **知识库** | AI 回答的专业性 |
| React 动效与视觉 | **Figma 导入** + 对话调优 + frontend-design skill | 还原度 |
| 真实用户数据需求 | **扫码授权**（抖音账号）/ 抖音数据 API | 个性化与真实性 |

### 各 Part 任务与验收标准

**PART-P（此阶段为准备态）**
- 任务：① 环境就绪——全员完成飞书账号、扫码加入"2026抖音AI创变者计划"账号、下载安装安全浏览器（Mac/Win 对应版本），确认能收到组织确认邮件/短信；② 研读章程平台章节，产出《平台操作预案》：首轮 vibecoding 需求描述稿（把目标人群/刷到场景/四页结构/数据表结构/交互一次讲清）+ 预计 15–20 轮的迭代提示词序列 + 疑问清单（留给 7.24 后答疑/workshop）。
- **验收（DoD）**：三人设备上安全浏览器可打开 douyin-ai.bytedance.net 登录页；《平台操作预案》文档评审通过，首轮描述稿经全员朗读一遍无歧义。

**PART-D**
- 任务：① 机位库 schema v1 定稿并填充**深圳 25 个机位**的结构化数据（坐标、朝向角、场景类型、最佳时段、焦段/构图模板、文案槽位；样张字段留空待 C 供图）；② 光线引擎 v2：顺逆侧光判定函数 + 评分公式 v2（云量分层/湿度/能见度/太阳高度角加权）写成一页纸规格；③ **预计算表**：SunCalc 是纯数学，离线算好深圳（及全部机位坐标）7.24–8.10 逐日的日落时刻、golden/blue hour、逐 10 分钟太阳方位角，导出 JSON——即使平台调不了外部 API，光线数据也万无一失；④ 天气接入双预案：在线 API 版 / 每日人工刷新版（对话插入或重导表数据，值守早晚各一次）；⑤ 豆包提示词工程初稿：输入结构化数据 → 输出一句行动文案 + 三句拍摄建议，人工精修 10 组黄金样例做 few-shot（初赛精修文案直接复用为样例库）。
- **验收**：机位 JSON 通过自写校验脚本（字段完整率 100%）；评分公式一页纸含 3 个真实日期的回测示例且结论合理；预计算表覆盖 25 机位 × 18 天；提示词在网页版豆包上盲测 10 次，≥8 次输出达到"可直接上卡"水准。

**PART-C（本阶段最急，7.11 当天启动——外联周期最不可控）**
- 任务：① 建 30 人目标创作者清单（小红书/抖音/**可颂**上的深圳机位内容作者，可颂创作者优先——"素材来自可颂创作者授权"本身就是生态叙事的实证）；② 私信模板与授权规范：说明学生比赛用途、署名方式、使用范围（比赛作品/海报/视频内展示），对方回复明确"同意"的聊天记录截图即为留存凭证，统一归档共享盘；③ 授权洽谈中顺带 5–8 个轻访谈（为什么拍/怎么找机位/最大痛点），语录供 PART-N；④ 未拿到授权的机位列入 7.28 实拍清单并排好路线（深圳湾—人才公园线，日落约 19 点后，一晚可扫 4–5 个机位，每机位样张 1 张 + 步导图 3–5 张）。
- **验收**：7.23 前 **≥15 个机位拿到授权样张**，每张可追溯到凭证与署名信息；≥5 条可引用访谈语录；7.28 实拍清单含机位顺序、到达时刻、拍摄清单，精确到半小时。

**PART-X**
- 任务：① React 原型改版为 v1.1 交互规格：按新四页结构（封面 → 轻导航 → 攻略[含导航悬浮窗+样张流] → 快拍[构图模板+滤镜预设]），不追求完美，追求"每个关键交互都有可演示的参照物"；② Figma 四页高保真稿（供平台 Figma 导入）；③ 设计 tokens 表：色卡、字体、间距、动效时长与缓动曲线；④ 《首 5 秒规范》：逐元素定义出现时序与信息优先级（对应"前 5 秒原则"）。
- **验收**：原型 v1.1 真机可完整演示四页；Figma 链接全员可访问且页面命名规范；tokens 表与《首 5 秒规范》各一页纸，PART-P 确认"拿到即可开工"。

**PART-N**
- 任务：① 商业叙事一页纸定稿（抖音制造心动 → 追光给此刻最短路径 → 可颂承接；vs 小红书"已想查攻略" vs 追光"还没开始查已被打动"；vs 美团交易入口 vs 追光体验入口）；② 可颂图文步导拆解报告（截图逐帧分析信息结构与节奏，直接反哺 X 的攻略页规格）；③ 海报概念稿 2 版；④ 游园会展陈方案草案（展位物料清单：海报、双手机——一台循环演示一台供评委扫码、二维码立牌、30 秒话术）。
- **验收**：叙事一页纸能让一个陌生同学在 60 秒内复述出三层结构；拆解报告让 X 明确采纳 ≥3 个设计决策；海报两版方向可供选择。

**Gate 0（7.23 晚，全员会）**：逐项过 DoD。任何一项不达标 → 判定是否降级（如机位授权 15→10）并记录到风险登记册。通过后 P1 开闸。

### 7.24 当天：能力测绘日（全员投入，当日必须出结论）

PART-P 主导，产出《平台能力报告》，逐项回答（含实验证据截图）：

1. 自定义 feed 卡的动效自由度——时间条拖动这类手势交互能否实现？到什么颗粒度？
2. 小程序内能否获取用户定位（GPS）？
3. 工具/Skill 能否调用外部 HTTP API（天气、地图）？还是仅限平台内置能力（章程提过集成抖音视频/图文搜索）？
4. 数据库表：JSON 附件导入的规模上限、查询方式、卡片如何读表？
5. 生成式模型：@豆包 调用的延迟与稳定性？能否带 few-shot 上下文？
6. 知识库挂载后模型引用效果如何？
7. Figma 导入的还原度实测（拿 X 的一页试）？frontend-design skill 效果？
8. 扫码授权能拿到哪些真实用户数据？抖音数据 API 的可用范围？
9. 真机预览流程与刷新时延？
10. **发布审核**：从"确认发布"到链接可用要多久？（当天就试发布一个玩具项目实测）
11. 协作权限添加流程（三人都要能进项目；注意评委可随时访问任一项目——工作区保持整洁）。
12. 每团队仅可提交 1 个项目——实验放沙盒项目，主项目从第一天就保持干净。

**当晚触发决策树（总设计师会签）**：

- 外部 API 可调？ **是** → 实时天气链路｜**否** → 每日人工刷新天气表（值守制），太阳数据走预计算表（已备好，零风险）
- GPS 可用？ **是** → 附近机位真实距离与到达时刻｜**否** → 默认深圳 + 显式城市选择器（评委在深圳，默认值即正确值）
- 手势级动效可实现？ **是** → 完整时间条色卡拖动｜**部分** → 点按分段切换色卡（保留"光在变"叙事）｜**否** → 自动播放的色彩过渡 + 关键帧停留
- 审核时长 X 小时 → 倒推 D3 发布死线 = 12:00 − X − 1h 安全垫

**D3**：09:00 最终数据刷新（当天深圳真实天气——若当晚有晚霞，卡片直接预告"今晚 X 点深圳湾"，评委刷到的就是给他本人的真预报，这是我们最大的戏剧性时刻）；**按 P1 实测审核时长倒推，最晚 10:00 前确认正式发布**；11:30 链接填入飞书表格并三人交叉核对；12:00 黑客松结束；14:00–17:00 游园会——一人守展位执行 30 秒话术（先递手机再开口），一人机动引流与记录评委问题，一人参加 16:00 选手互评（既是礼节也是总决赛情报）；17:30 闭幕。

## 9. 风险登记册（按杀伤力排序）

1. **平台动效自由度不足，原型还原度低** → 7.24 当天测绘即知；降级序列已在决策树中预置（拖动→点按→自动播放），叙事核心"光在变化"三种形态都能成立。
2. **发布审核时长不可控** → P1、P2 各做一次试发布实测；D3 发布死线按实测倒推并留 1 小时安全垫。
3. **授权进度不及预期** → 双保险：7.28 实拍窗口 + 降级为"10 精修机位 + 若干无样张的纯数据机位"（攻略页样张位显示"待你来拍下第一张"，反而成为 UGC 叙事）。
4. **外部 API 不可用导致天气断供** → 每日人工刷新 SOP + 太阳数据预计算表兜底；光线部分零外部依赖。
5. **正式赛题与预判偏差** → 底层能力（LBS×实时数据×机位×步导×预设）覆盖赛道三全部鼓励方向，D1 晚只换叙事外壳。
6. **C 的带宽过载**（授权+素材+海报+展陈集中在一人）→ 授权外联由提出该策略的成员主抓；海报视觉在 P0 就出概念稿，避免 D2 临时创作。
7. **现场加功能的诱惑** → D2 夜间硬性冻结；新想法一律进"总决赛 backlog"（8.11 北京见）。
8. **素材合规争议** → 凭证归档 + 署名核对为 Gate 2 必查项；宁缺毋滥。
