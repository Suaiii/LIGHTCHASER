## 1｜第一性原理（六条不可约减的事实，所有任务由此推导）

- **F1 · 前 5 秒定生死**：赛道三评审锚点是"用户在刷到的一瞬间，是否就能被打动、被满足，并自然产生一次互动"。体验完整性占 30%。→ 一切设计以刷到后前 5 秒的信息效率为最高优先级。
- **F2 · 我们不写代码，我们写"让 AI 写对代码的话"**：作品必须经「抖音AI平台」以 vibecoding 方式产出（feed 卡 + 小程序，真实进入抖音 feed）。→ 规格、数据、提示词的质量 = 产品质量。本编队的产出物就是这些"话"。
- **F3 · 评委即用户，深圳即现场**：评委在深圳、在比赛当天下午亲手扫码体验。→ 数据的"此刻真实性"（当天深圳的真评分、真日落）是最强的说服力，任何写死的假数据都是自我降级。
- **F4 · 平台 7.24 才开门，现场只有 40 小时**：→ 一切可离线预制的（太阳数据、机位库、文案样例、规格、话术）必须在 7.24 前预制完毕；平台期只做"翻译与还原"，现场期只做"整合与发布"。
- **F5 · 开发只有两个人**：→ 人的稀缺资源是决策与验收带宽，不是打字速度。所以每个任务写成 agent 文件、交付条件二元化（打勾即验收，不需要思考），人只做机器做不了的事：拍板、外联、现场执行。
- **F6 · 素材合规一票否决**：章程严禁未授权素材。→ 每一张图有可追溯的权利链（授权凭证或自拍记录），宁缺毋滥。

## 2｜共享上下文胶囊（各 agent 文件均引用，此处为唯一权威版本）

**产品**：追·光——刷到即知"今晚值不值得为天空出门"的抖音 feed 卡 + 承接出门行动的小程序。定位：抖音制造心动 → 追光判断此刻是否值得行动并给最短路径 → 可颂承接机位/攻略/作品沉淀。

**四页结构**：P1 封面详情（评分 + 时间条色卡互动）→ P2 轻导航（路线 + 倒计时）→ P3 机位攻略（样张 + 站位 + 朝向罗盘 + 图文步导 + 导航悬浮窗）→ P4 快拍（构图模板 + 3 滤镜预设 + AI 建议 + 发布引导）。社区内容已并入 P3 样张流，无独立页。

**视觉 tokens（源自初赛 追_光.html，权威值）**：天空色卡 `#3a4a6b 灰蓝 → #e0a060 橘 → #c84858 深红 → #5a3870 紫`；主色追光橘 `#ff8a3d`；辅 `#ffd49a`；深色底；中文 Noto Sans SC，展示衬线 Fraunces，等宽 JetBrains Mono。

**评分等级**：≥75 值得跑出门 ／ 45–74 顺路看看 ／ <45 今天歇着（劝退 + 明日预告）。

**评审表**：场景洞察 20 ／ AI×产品 15 ／ 体验完整性 30 ／ 用户价值感 20 ／ 延展潜力 15。评审形式：评委线上看提交 + 游园会真机体验（无 8 分钟路演）。

## 5｜运行规则（人如何驱动 agent）

1. 把单个 agent 文件 + 其「输入」一并交给执行 AI（或人），不要求它读其他文件——每份文件自带上下文胶囊。
2. 交付时必须附《检查报告》：逐条执行该文件的「检查任务」，每条附证据（脚本输出/截图/链接）。无检查报告 = 未交付。
3. 验收人只对照「交付条件」打勾；出现"感觉不对但条件都满足"→ 说明交付条件写漏了，修文件，不口头补锅。
4. 任何 agent 触发自己文件里的「升级条件」→ 立即停手，问题写成一句话抛给 H1/H2，不空转。
5. 所有产出物入仓库 `/agents_output/<agent编号>/`，文件名带日期版本。
