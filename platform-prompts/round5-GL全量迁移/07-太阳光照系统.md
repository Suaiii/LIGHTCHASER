# R5-07 · 太阳光照系统（真实几何 · 天气驱动 · 日夜变化）

**配套上传**：`materials/lib/suncalc.js` + `materials/gl/source/zg-sun-helpers.js` + `materials/gl/gl-migration-spec.md`（§4）+ `materials/data/sun_events.v1.json`（预计算兜底表）

> 这一条是 R5-03 第二段的**完整替代版**。R5-03 只让太阳"有个方向"，本条让它**是真的**：
> 换城市、换日期、换时刻、换天气，画面都跟着变；哪一份数据是实算的、哪一份是演示的，屏幕上写清楚。
>
> **背景（为什么专门开一条）**：我们自己的原型犯过一个错——演示模式下把服务端实算的太阳位置扔掉，
> 换成写死的「方位角 283°、高度角 7°」。结果是：任何城市、任何日期，演示时太阳永远在同一个角度；
> 而 HUD 左边还按真实时间显示「距峰值 532 分钟」，右边写「演示光位 18:40」，同屏两个时钟打架。
> **五段提示词就是为了让平台不要重蹈这个覆辙。分段发，一段做完验收再发下一段。**

## 第一段：太阳位置的三档来源（禁止写死角度）

```
地图的光照方向要用真实太阳位置驱动。我上传了 suncalc.js（BSD-2，约 300 行，
纯几何计算，不联网），把它整段内联进项目。

太阳位置按优先级取三档，每一档都要在界面上标明用的是哪一档：
① 实时：有真实定位和当前时间时，用 SunCalc.getPosition(当前时间, 纬度, 经度) 实算。
② 演示时刻：演示模式下，把时间固定成一个演示时刻（默认当天 18:40），
   但仍然用 SunCalc 在真实经纬度上实算那个时刻的太阳位置。
③ 兜底：suncalc 内联失败时，读我提供的预计算表 sun_events.v1.json 取最接近的一条。

换算公式（SunCalc 的方位角是从正南起、向西为正，必须换成罗盘方位）：
  方位角(度) = (azimuth × 180 / π + 180 + 360) % 360
  高度角(度) = altitude × 180 / π

一条硬规则：**演示可以固定时刻，绝对不可以固定角度。**
不许在代码里出现写死的方位角或高度角数字。
理由：写死角度之后，深圳和上海的太阳会在同一个方向，六月和十二月的太阳也在同一个方向，
用户一眼就能看出这是假的。固定时刻＋实算，才能既保证演示时段好看、又保证数值真实。

地图的初始 bearing 设成「太阳方位角 减 60 度」，让受光面正对镜头。
```

## 第二段：全屏统一一个时间基准

```
页面上所有和时间有关的读数必须用同一个时间基准，不许一半用真实当前时间、
一半用演示时刻。具体是这四处：
1. 顶部「距峰值 N 分钟」的倒计时
2. 太阳方位角/高度角读数
3. 底部结论卡的「步行 N 分钟 · HH:MM 到 · 正好赶上／峰值已过 N 分钟」
4. 天空光晕的颜色（它由太阳高度角决定）

做法：把「当前生效时刻」抽成一个变量，实时模式下等于真实当前时间，
演示模式下等于演示时刻，上面四处全部读它。

自检方法：把演示时刻设成 18:40，看倒计时算出来的到达时刻是不是也在 18:40 附近。
如果倒计时显示 500 多分钟而太阳显示 18:40，就是基准打架了，必须修。
```

## 第三段：天气驱动光照强弱

```
光照要随天气变，不能晴天阴天长一个样。天气数据我会通过接口给你，
字段是：云量百分比 cloudCover、相对湿度 relativeHumidity、
能见度公里数 visibilityKm、天气代码 weatherCode（WMO 标准码）。

按下面这套映射改渲染参数（这是可解释的线性映射，不要自己加别的因子）：
1. 平行光强度 = 0.55 × (1 − 0.6 × 云量/100)
   —— 满云时降到约 0.22，仍有环境光，不能全黑。
2. 建筑投影不透明度 = 0.30 × (1 − 云量/100)
   —— 阴天没有硬影子，这一条比光强更影响真实感。
3. 天空光晕不透明度 = 0.32 × (1 − 0.5 × 云量/100)
   —— 阴天的霞光是闷的，不是没有。
4. 远景雾：能见度低于 10 公里时，在远处叠一层雾，
   雾的不透明度 = (10 − 能见度公里) / 10，上限 0.45，雾色用当前天空色。
5. 天气代码属于降水或雾类（WMO 45/48 雾，51-67 雨，71-77 雪，80-99 阵雨雷暴）时，
   整体饱和度降到 0.75，并把光强再乘 0.8。

无法拿到天气时：全部参数走晴天默认值（云量按 0 算），
并在界面上标注「天气·默认晴天（未接实时）」，不许假装接了。
```

## 第四段：白天不能是夜色

```
现在底图是一套写死的夜幕配色，中午看也是夜晚，这不对。改成按太阳高度角插值：

三套锚点：
- 白天（太阳高度角 ≥ 20°）：用地图样式的原始配色，只把整体饱和度降到 0.85，
  不做压暗。白天就该是亮的。
- 黄昏（高度角 5°）：原始配色与夜幕配色各占一半。
- 夜晚（高度角 ≤ −6°）：完全用夜幕配色（背景 #141824、水域 #17203a、
  绿地 #1a2230、建筑 #1e2536、主干道 #5d6884、次级道路 #3b4560、
  其他线 #242d44、文字 #c0c8dd 配描边 #0d1017）。

中间按高度角线性插值。插值只在「原始色」和「夜幕色」两个端点之间做，
不要引入第三种颜色、也不要用色相旋转之类的换算——我们试过通用混色公式，
它会把绿地混成青色、把品红混成紫色。

天空光晕的颜色也随高度角走这张表（表内线性插值）：
  -6°→#5A3870  0°→#8A4068  3°→#C84858  8°→#DE6B48
  16°→#E0A060  30°→#EBC28E  55°→#F2E2C4
我上传的 zg-sun-helpers.js 里有现成的插值函数，直接用。
```

## 第五段：把数据来源写在脸上（F6 红线，务必单独发）

```
屏幕左上角固定显示三行小字，如实说明每一项数据的来源，
不许折叠、不许悬停才出现、不许只写在说明页里：
1. 太阳：三选一 —— 「太阳·实时方位」／「太阳·18:40 实算（演示时刻）」／
   「太阳·预计算表兜底」。演示时刻那档必须把时刻数字写出来。
2. 天气：「天气·实时」／「天气·默认晴天（未接实时）」。
3. 地图数据：「道路·瓦片实时 ｜ 建筑·视口实时 N 栋」，
   用离线兜底数据时必须改写成「建筑·离线包兜底 N 栋」。

判断标准很简单：任何人截一张图，都能分清哪些是真数据、哪些是演示数据。
做不到这一点，这一页就不能对外演示。
```
