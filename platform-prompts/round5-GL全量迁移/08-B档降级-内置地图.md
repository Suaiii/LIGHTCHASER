## 第二段：地图 + 筛选 + 列表（B 档骨架）

```
做一个上下两段的地图页：
上半 60% 高度是地图，下半 40% 高度是照片列表，列表可滚动、地图不滚动。

地图：
- 用你的内置地图组件，暗色主题；没有暗色主题就在地图上叠一层
  半透明深色蒙版 rgba(20,24,36,0.35)，保证上面的橙色元素能浮起来。
- 中心用我给的坐标，缩放级别 14。
- 照片数据来自我上传的 photos.v1.json，每条一个标记。

地图上方两个控件：
- 左边：双段胶囊「今天 / 本周」，宽 136、高 36、距顶 12，默认选中「今天」。
  今天 = 当天 0 点到现在；本周 = 往前推 6 天 0 点到现在（滚动七日，不含未来时间）。
  切换后列表和地图标记必须真的跟着变；某一档没有数据就显示
  「这一档还没有照片」，绝对不许拿另一档的数据填上去假装有。
- 右边：光位罗盘（下一段单独说）。

下半列表：每行一个照片项，左边缩略图，右边两行——
第一行机位名（加粗），第二行「几小时前 · 距离 km」，最右边一个「示例」小角标。
按时间倒序。

地图和列表必须联动（这是这一页的核心，不能省）：
- 点地图上的标记 → 列表滚动到对应那一行并高亮 1.2 秒
- 点列表某一行 → 地图移动到该点居中（不要改变缩放级别，来回跳会晕）
```

## 第四段：光位罗盘 —— 3D 掉了之后，靠它撑住"追光"

```
右上角放一张小卡，底色 rgba(14,17,26,0.72)、模糊 10px、1px 白色 12% 描边、圆角胶囊。
三行内容：
第一行（等宽字体 10.5px）：☀ 283° · 高 7.0°   ← 太阳方位角和高度角
第二行：受光关系 —— 拍摄朝向与太阳方位角的夹角，
        小于 45 度写「逆光 · 出剪影」，45 到 135 度写「侧光 · 好拍」，
        大于 135 度写「顺光 · 色彩正」。
第三行（9.5px）：数据来源，见下。

太阳位置的取法（这条是硬规则，照抄）：
① 有真实定位和当前时间 → 用 SunCalc.getPosition(当前时间, 纬度, 经度) 实算，
   第三行写「太阳·实时方位」。
② 演示模式 → 时间固定成演示时刻（默认当天 18:40），但仍用 SunCalc 在真实经纬度上
   实算那个时刻，第三行写「太阳·18:40 实算（演示时刻）」。
③ suncalc 用不了 → 读预计算表，第三行写「太阳·预计算表兜底」。

换算：方位角(度) = (azimuth × 180 / π + 180 + 360) % 360，高度角(度) = altitude × 180 / π
（SunCalc 的方位角从正南起、向西为正，必须换成罗盘方位）

绝对不许在代码里写死方位角或高度角的数字。
写死之后深圳和上海的太阳会在同一个方向、六月和十二月也在同一个方向，一眼假。
演示可以固定时刻，不可以固定角度。
```

## 第五段：天空色带 + 路线（收尾，成本极低但很值）

```
1. 页面最顶部加一条 6px 高的横色带，颜色按太阳高度角在这张表里插值：
   -6°→#5A3870  0°→#8A4068  3°→#C84858  8°→#DE6B48
   16°→#E0A060  30°→#EBC28E  55°→#F2E2C4
   一根色条就能让人看出"光在变"，不许省。
2. 路线：默认不画，用户点「按金线去这里」才画。
   能设颜色宽度的话：外层 #ff8a3d 宽 16 半透明，芯线 #ffd49a 宽 4.5。
   只支持单色的话：#ff8a3d，宽 5。终点加标记 + 机位名胶囊。
   关闭后立刻移除，任何时候地图上不许同时存在两条高亮路线。
```

## 第六段：数据来源标注（F6 红线，务必单独发）

```
屏幕左上角固定三行小字，如实说明数据来源，不许折叠、不许悬停才出现：
1. 太阳：「太阳·实时方位」／「太阳·18:40 实算（演示时刻）」／「太阳·预计算表兜底」
2. 天气：「天气·实时」／「天气·默认晴天（未接实时）」
3. 地图：地图组件的数据来源署名，按组件要求保留

另外：所有演示数据的「示例」「演示」字样必须在三个地方都出现——
地图标记上、列表行上、详情卡上。不许只标一处。
判断标准很简单：任何人截一张图，都能分清哪些是真数据、哪些是演示数据。
```
