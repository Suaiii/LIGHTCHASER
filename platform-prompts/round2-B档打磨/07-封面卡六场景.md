## 粘贴给平台 AI（第一段：照着做一张）

```
按我上传的这张图（01.jpg）和坐标表（card_spec.md）做首页卡片，画布 430×860。
关键要求：
1. 背景是整屏铺满的照片，等比裁切填满、不许拉伸变形。
2. 照片上压三层遮罩，顺序不能换：
   ①顶部 0-430px：从 #070b17(不透明度0.78) 渐变到透明
   ②底部 522px 往下 338px：从透明渐变到 #100b11(不透明度0.92)
   ③整屏一层 #6e51a5 到 #e47143 的紫橙渐变，整层不透明度只有 0.10
   第三层是让不同来源的照片统一色温用的，不许省。
3. 左上大标题 45px 加粗、字距 -1px，最多两行，压在顶部遮罩上。
4. 右上评分卡：118×112 圆角 17，底色 #20161bd9 带 1px #ffffff2e 描边。
   里面从上到下是：11px 英文分类标（字距 1.2）、45px 斜体大数字、
   紧跟 17px 的 /100、13px 加粗结论词。
5. 下方信息卡：386×140 圆角 20，酒红底 #651938(不透明度0.93)，
   左边 49×49 圆角 13 的图标块 #a4385a，右边两行：18px 加粗机位名、
   12px 的「距离 步行时长 时刻」。中间一条 #ffffff36 分割线，
   线下左边 12px 行动理由，右边 113×36 圆角 20 的橙色 #ff9f40 按钮，
   按钮文字 14px 加粗、颜色 #321618（深色字压橙底，不是白字）。
6. 全卡只用一种字体：PingFang SC / Noto Sans SC。
做完截图给我，我要对比比例。
```

## 粘贴给平台 AI（第二段：换数据复用成六张）

```
版式确认好了。现在用同一套版式做六张卡，只换数据不换布局——
数据在我上传的 scenes.json 里，六条对应六个场景：
蓝调 / 云隙光 / 日出 / 树影 / 林下围炉 / 夜市。
每条要读的字段：headline（大标题）、score_label（英文分类标）、
score（大数字）、verdict（结论词）、spot_name（机位名）、
spot_meta（距离行）、reason_line（行动理由）。
六张卡的坐标、字号、颜色、遮罩必须完全一致，只有文字和背景照片不同。
标题只有第一条是两行（"蓝调仅剩"/"18分钟"），其余都是一行。
做完把六张排成两行三列给我看一眼。
```

## 粘贴给平台 AI（第三段：合规角标，务必单独发）

```
每张卡的评分卡正下方（x=282,y=245 起）加一个 44×16 的小胶囊，
写"示例数据"，底色 rgba(10,10,13,0.88)、白字 10px、1px 浅色描边。
这个角标必须一直显示，不许做成鼠标悬停才出现、也不许只写在说明页里——
因为卡上的分数、倒计时、距离目前都是演示值，不标出来就是误导用户。
六张卡每张都要有。
```

## 验收

- [ ] 单张卡：三层遮罩齐全（尤其那层 0.10 的紫橙调），照片没被拉伸
- [ ] 评分卡里四行信息层级对（分类标 < 大数字 > /100 > 结论词）
- [ ] CTA 按钮是**深色字压橙底**，不是白字（白字压橙会糊）
- [ ] 六张卡版式完全一致，只有文字和照片变
- [ ] **每张都有常显的「示例数据」角标**（F6 红线，这条不过不许对外演示）
- [ ] 机位名若用了 scenes.json 里的占位名（湖岸蓝调等），已知它们**不在真实机位库里**，对外前要换真名或明确标示例

## 我们这边的基线（供对照）

| 项 | 值 |
|---|---|
| 单卡画布 | 430 × 860（导出 2x = 860 × 1720） |
| 六场景覆盖 | 光线 3（蓝调/云隙/日出）+ 生活 3（慢行/围炉/夜市） |
| 分数区间 | 86–93，结论词六种（正是时候/值得出门/早起值得/适合出门/光线舒适/正在开场） |
| 行动理由字数 | 9–15 字（上限 15，场景 06 踩线） |
| 大标题字数 | 4–8 字 |

> 已知偏差（`card_spec.md §5`）：本稿强调色 `#ff9f40` 与 token 的追光橘 `#ff8a3d` 不一致，且新引入酒红系；评分数字用 PingFang 斜体而非 Fraunces。**先按本稿的值让平台复现**（这是负责人看过并认可的视觉），要不要统一到 token 是另一个决定。
