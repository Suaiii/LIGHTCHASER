# 封面卡连线手册（平台侧逐元素接数据 · 0726）

> 前提：A 包六表已导入平台数据库（至少 spots / sun_events / weather_daily 三张，封面卡只靠这三张 + 文案生成）。
> **纪律：一次连一根线，连完让它预览验证，再连下一根。** 每段"话术"直接粘贴给平台 AI。

## 连线顺序（易 → 难）

### 第 1 根：⑤机位名 + ⑥距离（只读 spots 表）

```
把卡上的机位名和距离改成从 spots 表读：取 id 为 "szs-004" 的记录（塘朗山郊野公园·观景平台），
机位名显示它的 name 字段；距离先用用户定位到该记录坐标的直线距离估算，显示成"x.x km · 步行约 x 分钟"
（步行按每公里 12 分钟算）。用户没给定位授权时，距离位显示"开启定位查看距离"。
```
验证：机位名变成表里的值（改表里一个字，卡上跟着变，才算真连上了）。

### 第 2 根：④峰值时刻 + 倒计时（读 sun_events 表）

```
峰值行改成动态：用当前机位 id + 今天日期查 sun_events 表，取 golden_hour/peak 时刻显示"峰值 HH:MM"；
倒计时=峰值时刻减当前时间，还没到显示"还有 N 分钟"，过了显示"已过峰值·明晚见"。
朝向"向西看"来自该记录峰值时刻的 azimuth（240°-300° 显示"向西看"）。
```
验证：显示的峰值时刻与表里今天那行一致。

### 第 3 根：①评分 + ②等级标签（sun_events + weather_daily 合算）

```
评分改成计算值：读 weather_daily 表今天的云量/湿度/能见度，按这个公式算 0-100 分：
基础分 60；低云量 20-60% 加 25 分、<20% 加 10 分、>80% 减 30 分；能见度>15km 加 10 分；
湿度<60% 加 5 分。结果限制在 0-100。
等级标签三档：≥75 显示"值得跑出门"，45-74 显示"可以出门碰碰运气"，<45 显示"今晚在家吧"。
```
验证：手改 weather_daily 里的云量，分数和标签应跟着变。
⚠️ 评分公式细节以 `agents_output/02/light_engine.js` 为准，上面是平台侧简化版——够用即可，**不加维度**（红线）。

### 第 4 根：③AI 标语（豆包生成 + 兜底）

用 `01-action-copy.md` 的提示词接生成模型，输入=当天评分档+天气+机位；**必须带兜底**：
```
生成失败/超时/超过 26 字时，改从 copy_corpus 表取兜底：按 scene+评分档+天气三个键精确匹配一行，取 hook 字段。
```
验证：把生成故意断掉（或改坏 prompt），卡上仍有兜底文案，不留空白。

### 第 5 根：Ⓑ1 导航按钮（测绘结论决定）

- 平台能吊起地图导航 → 接机位坐标发起步行导航；
- 不能 → 降级为"复制坐标+机位名"到剪贴板，toast 提示"已复制，粘贴到地图 App"。
把哪条路走通了回填 #19。

## ⚠️ 发布前 F6 红线自查（重要）

**weather_daily 目前是演示假数据**（表里 `_demo_note` 有标注）。卡上写着"AI 译自今天的气象"——只要天气还是假的，这卡就不能以"真实预报"姿态公开发布。二选一：
1. **接真天气**（推荐，一次到位）：让平台定时调 Open-Meteo（免费无 key）拉深圳当日云量/湿度/能见度写入 weather_daily，字段名不变，评分公式零改动；
2. 暂时接不了外部 API → 卡面加可见"演示数据"角标（不许只写在说明里）。

另外核对：卡上不应残留"上海"字样（那是原型壳的遗留，平台重建版不该有）。
