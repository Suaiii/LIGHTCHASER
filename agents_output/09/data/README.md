## alt 字段定案：az-only 版

`sun_events.azimuth_10min[].az`（方位角，度）已交付；`alt`（高度角）字段**同样已交付**（见下方结构说明）——早前"az-only / 待补 alt"是 HERMES-02 遗留的悬置话术，HERMES-02 已结案（issue #17 关闭），实测 `azimuth_10min` 每个采样点本就同时含 `az` 与 `alt` 两个数值（见 `sun_events.v1.json` 任意一条记录）。本 README 按 Gate 0 裁定书口径明确标注：**不再等、不再写"待补"**，字段现状即最终态。

`azimuth_10min` 结构：嵌套数组，每个元素 `{ t: "HH:MM", az: 度, alt: 度 }`，覆盖本地 16:00–20:30 每 10 分钟（28 点/日）。**期望整列按 JSON 文本字段导入**（不要拆成独立列），平台侧取用时按 `t` 做时间匹配。

## 建表话术（六段，各 ≤3 句）

### 1. spots（机位库）
表名：`spots`。包含深圳 25 个摄影机位的名称、坐标、朝向角、最佳拍摄时段、构图模板与图文步导，用于向用户推荐具体去哪拍、怎么拍。数据来自团队实地调研并经 OSM Nominatim 坐标反查核验，一次性导入为只读参考表，不接受用户端写入。

### 2. sun_events（太阳事件）
表名：`sun_events`。包含 25 机位 × 18 天（2026-07-24 至 08-10）每日日落/黄金时段/蓝调时段时刻，以及每 10 分钟一条的太阳方位角+高度角序列，用于驱动光线评分与地图光照方向。数据由 suncalc 离线几何库预计算生成（零外部依赖、可复算），一次性导入，`spot_id` 关联 `spots.id`。

### 3. weather_daily（天气日值 · 演示数据）
表名：`weather_daily`。包含当日与次日深圳的分层云量、湿度、能见度、天气代码与"是否有雨"字段，与 `sun_events` 联合驱动光线评分公式。**当前为演示用假数据**（文件内 `_demo_note` 已标注），正式版走 `weather_ops.md` 预案 A（Open-Meteo 在线 API）或预案 B（人工刷新）二选一接入，评分公式与字段名零改动；本表用 `gen_weather_daily.mjs` 按运行日一键重新生成。

### 4. copy_corpus（文案兜底语料）
表名：`copy_corpus`。包含 27 条按"场景×评分档×天气"三维取格键组织的人工精修兜底文案（`hook` 字段），供生成模型超时/输出违规/数据缺失时兜底调用，确保卡片文案位永不空白。取格规则：用当前 `scene`（sunset/exhibition/cafe）、评分档位 `bucket`（high/mid/low）、天气 `weather`（clear/cloudy/rain）三值精确匹配一行，命中即取该行 `hook`——27 = 3×3×3 全覆盖，无缺格。

### 5. user_prefs（用户偏好 · 空表草案）
表名：`user_prefs`。设计用于记录用户收藏机位、偏好场景与提醒时段，供未来个性化推荐/主动提醒逻辑读取；**当前零行数据，仅表结构占位**（`user_prefs.v1.schema.json`）。写入逻辑待真实用户账号体系或抖音扫码授权接入后再定，本次交付不产生任何读写操作，字段可在真正接入前自由调整（尚无消费方，不构成既有 schema 改动）。

### 6. photos（地图照片气泡）
表名：`photos`。包含 20 条深圳机位的照片气泡种子数据（作者、坐标、拍摄时间、图注、关联评分），用于板块二"追·光地图"的实时社区气泡展示层。**当前全部为团队生成的渐变垫图**（`data_nature` 字段已声明"非真实 UGC"），真实版由用户投稿经 `POST /api/photos` 写入并做深圳坐标围栏校验。
