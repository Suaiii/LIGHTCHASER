# 检查报告 · 太阳几何交叉核验（AGENT_02 补充件）

**触发**：负责人质疑"太阳定向光是不是根本算错了、是不是只是个 mock"。
**做法**：不做口头辩解，用第二套**独立实现**的算法对拍。
**脚本**：`scripts/verify-sun.mjs`（`node scripts/verify-sun.mjs`，退出码非 0 即不达标）
**日期**：2026-07-29

## 方法

| 项 | 说明 |
|---|---|
| 被验对象 | 项目实际使用的换算：`SunCalc.getPosition()` + `(azimuth×180/π + 180) % 360`，与 `lib/sunset-service.js:30-34` 一致；前端 `public/zg-sun-runtime.js` 的 `sunFromSunCalc` 用同一式子 |
| 对照算法 | NOAA Solar Position Algorithm，脚本内**独立实现**（儒略日 → 平黄经/平近点角 → 中心差 → 视黄经 → 黄赤交角 → 赤经赤纬 → 地方时角 → 地平坐标），不引用 suncalc 任何代码 |
| 样本 | 3 城 × 4 时刻 = 12 组。深圳·南科大 / 上海·人民广场 / 漠河（高纬极端，验证不只在低纬成立） × 06:00 / 12:00 / 18:40 / 22:00（UTC+8） |
| 判据 | **天球角距 < 0.3°** |

### 为什么判据是角距，不是方位角差值

首版用「方位角差 < 0.5° 且高度角差 < 0.5°」判，深圳 12:00 一组报失败：方位角差 **0.920°**，
而同一组高度角差只有 **0.001°**。原因是那一刻太阳高度 81.89°、接近天顶，**方位角在天顶附近是病态量**——
方向只要动一点点，方位角读数就会大幅摆动。物理上有意义的一致性度量是两个方向矢量的夹角（角距）：

```
角距 = arccos( sin(alt₁)sin(alt₂) + cos(alt₁)cos(alt₂)cos(Δaz) )
```

换判据后该组角距 0.130°，与其余 11 组同量级。**这是修正判据，不是放宽阈值**：
换成角距后阈值反而从 0.5° 收紧到 0.3°。

**误差高度一致（0.129–0.131°）值得单说**：这是系统性常数偏差的特征，来自两套算法对光行差/章动等
小项的处理差异，而不是随机错误。若换算式写错（比如方位角起算点弄反），误差会随时刻与纬度剧烈变化，
绝不会稳定在 0.13°。**这组数据本身就是"没算错"的最强证据。**

## 结论与边界

**太阳几何没有算错。** 项目的方位角/高度角换算与 NOAA 独立算法在 0.13° 内一致，
且这个一致性在深圳、上海、漠河三地与全天四个时刻上都成立——说明它**是真几何，不是 mock**，
换城市换时刻数值会正确跟着变。
