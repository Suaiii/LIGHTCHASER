# 追·光 大区赛转型升级计划
**深圳赛区 · 赛道三「城市生活的即时美好」 · 7.28–8.1**
（基于：大区赛章程 instruction + 思路.md + 初赛代码库现状，编写日期 7.11）

---

## 0. 一页纸摘要

初赛的「追·光」是一张晚霞预报卡片，赢在动画和信息流原生形态。大区赛的评审逻辑变了：**完成度与技术实现权重最高，评委会现场真机验证、可能输入任意地点，只有预置数据会被重扣分**。同时思路.md 给出了新定位：追光不再是晚霞工具，而是「抖音制造心动 → 追光给出此刻的最短行动路径 → 可颂承接机位与攻略」的中间层，把"出片"从摄影扩展为抖音语境下的生活方式表达。

因此这次升级做四件事：

1. **叙事转型**：从「晚霞预报」升级为「即时美好的行动引擎」——晚霞是旗舰场景，另建 1 个非光线依赖的扩展场景（展馆/创意园）证明泛化能力。
2. **结构重构**：卡片四页改为 封面 → 应用内轻导航 → 机位攻略（图文步导 + 导航悬浮窗）→ 快拍（AI 构图 + 滤镜预设）。
3. **真实数据能力**：任意地点输入 → 地理编码 → 实时天气 + 太阳轨迹 → 评分 → 机位 → 真实路线，全链路自动化；深圳精选机位库人工精修打底。
4. **最后 100 米**：机位结构化（站位坐标 + 朝向角 + 样张），到达后进入「样张对齐模式」（罗盘 + 半透明样张叠加），直接回应路演质疑"你的导航到底有没有效"。

赛前两周把以上四件事做到 80%，现场 48 小时只做本地化打磨、导师反馈迭代和交付物冲刺。

## 1. 形势判断：大区赛和初赛的三个本质区别

**评分结构变了。** 章程给出的维度里，完成度与技术实现约占 30%，是单项最高；创新性、用户价值、商业与生态价值各约 20%，路演约 10%。初赛靠"演示效果 + 概念"能赢，大区赛章程明确提示：纯概念、纯 UI 演示的作品处于劣势。

**演示方式变了。** 真机演示是必选环节，评委可能现场输入任意地点/时间验证。预置数据只能作兜底，如被发现只有预置数据而无真实数据能力，完成度大幅扣分。初赛的 `?demo=high/mid/low` 三套预生成数据这次只能当降级方案，不能当主菜。

**主场在深圳。** 比赛地点即演示地点——评委现场输入的"任意地点"大概率是深圳地名。这反而是我们的机会：把深圳做成机位库精选样板城市，评委输什么我们都有精修内容接住。

一个必须马上确认的规则问题见第 10 节：48 小时协作开发是否允许携带初赛已有代码继续迭代（大区赛作品本来就是初赛晋级作品的延续，通常允许，但要问清楚并在文档里明确标注初赛 → 大区赛的迭代内容）。

## 2. 产品转型：定位与叙事

### 2.1 新定位（照思路.md 收敛成一句话）

> 追·光是抖音用户从「刷到心动」到「真的出门」之间的行动引擎：抖音制造心动，追光判断此刻值不值得行动并给出最短路径，可颂承接机位、攻略与作品沉淀。

三条推论，直接写进文档和 PPT：

- 追光不与可颂竞争，它是抖音流量通向可颂、通向本地生活攻略市场的**过渡层**；
- "出片"不只是摄影——餐饮、美术馆、演出、骑行、citywalk 都能出片，它是抖音语境下的生活方式表达；
- 小红书解决"我已经想查攻略了"，追光解决"我还没开始查，但我已经被打动了"——**时间差**就是生态位。

### 2.2 场景策略：一个旗舰 + 一个扩展，不贪多

- **旗舰场景：晚霞/城市光影**（保留初赛全部积累）。时间敏感性最强、光线引擎最能展示技术深度、动画资产最全。
- **扩展场景：展览/创意园（如 OCT-LOFT、深圳当代艺术与城市规划馆）**。选它的理由：不依赖天气和光线，证明产品逻辑可泛化；天然挂接门票/团购，是商业生态论证的实物例子；数据结构与晚霞机位完全复用（POI + 机位 + 步导 + 预设）。
- 餐饮/咖啡出片只做**数据层演示**（卡片里出现 1–2 个咖啡馆窗光机位即可），不单独做页面。48 小时内做三个场景是自杀式扩张。

### 2.3 竞争回答（路演问答预制弹药，也写进文档商业部分）

- **vs 小红书**：小红书是"检索 + 收藏"，决策链路长、内容会吃灰；追光是"此刻 + 行动"，刷到即出门。我们不做攻略社区，做攻略的**触发器**。
- **vs 美团**：美团是交易入口（解决吃什么、多少钱），追光是体验与创作入口（解决怎么把生活过成值得记录的内容），交易可以导给美团式的团购模块，我们收的是转化入口的位置。
- **vs 可颂**：不是竞争而是喂给——可颂有机位、路线、图文步导的沉淀，缺的是"用户刚产生冲动的那一刻"的入口，追光就是那个入口。

## 3. 产品结构升级：四页卡片重构

初赛结构：封面 → 路线 → 社区 → 快拍。按思路.md 重构为：

**P1 封面卡（改造）**
保留评分 + 峰值时间 + 一句话行动建议的骨架，两处升级：场景类型标签（晚霞 / 展览 / 咖啡…），支持多场景数据；行动按钮文案由 LLM 按实时数据生成（"往西走，还来得及" / "现在去两馆，人少光好"）。时间条 + 色卡互动原样保留——这是初赛的灵魂和动画优势，一帧都不能丢。

**P2 应用内轻导航（大改）**
从示意 SVG 路线图升级为真实地图：高德 JS API（现场有测试配额）+ 真实步行路线 + 光区/机位标记叠加。"轻"的含义是不跳出信息流——地图嵌在卡片内，顶部保留倒计时（距峰值 XX 分钟），底部一条"步行 12 分钟 · 18:31 到达 · 正好赶上"的结论句。初赛 OSRM 路线能力平移过来做兜底。

**P3 机位攻略页（新建，吸收原社区页）**
这一页对标可颂的图文步导，是回应"导航有效性"质疑的主战场：

- 机位卡：样张大图 + 站位描述（"人才公园 F 栈道，靠海第二个灯柱旁"）+ 朝向角（如 265°，配罗盘小组件）+ 最佳时段 + 焦段建议；
- 最后 100 米图文步导：3–5 张实景步骤图（学可颂的形式，素材必须自拍，见 5.3 版权红线）；
- **导航悬浮窗**：进入本页后 P2 的地图缩成画中画小窗悬浮在角落，保持"在路上"的连续感——这是思路.md 点名的交互，也是很好的动画秀肌肉点；
- 原社区页的"附近追光者作品"降级为本页底部的样张参考流，不再单独占一页。

**P4 快拍页（升级）**
回应"预设够不够"的质疑：

- 取景框构图模板叠加：三分线/引导线/地平线，按机位数据自动选;
- 滤镜预设：每个机位/光线状态绑定 3 个预设（CSS filter 或 WebGL LUT 实时预览）；
- AI 构图建议：豆包 API 输入{场景、天气、时刻、机位朝向}，输出一句构图建议 + 推荐滤镜，预生成文案兜底；
- 一键"发布"带话题与定位（演示到发布浮层即可，不必真发）。

到达对齐模式（P3 的杀手锏，可行且 48h 内能做完）：用 DeviceOrientation API 读罗盘朝向，屏幕上箭头引导用户转到机位朝向角，对准后样张以 40% 透明度叠加在取景框上——"照着这张拍"。iOS 需要 HTTPS + 用户手势触发权限，做静态罗盘降级。

## 4. 三大能力建设

### 4.1 导航有效性（路演质疑 #1）
分三层递进，文档里就按这三层写：城市级（评分告诉你值不值得出门）→ 街区级（真实路线告诉你怎么去）→ 机位级（站位 + 朝向 + 样张对齐告诉你站哪、朝哪、拍什么）。初赛只有前两层，这次补齐第三层。

### 4.2 拍摄预设（路演质疑 #2）
预设 = 构图模板 + 滤镜 LUT + 参数建议 + AI 一句话，全部挂在机位数据上而不是全局配置，这样"每个机位有自己的拍法"这句话在演示里是真的。

### 4.3 光线引擎加深（思路.md：对光源推算需要更深了解）
在 SunCalc 已有的日落时间/方位角/黄金蓝调时段之上加三件事：

1. **顺逆侧光判定**：机位朝向角 vs 实时太阳方位角 → 输出"此刻该机位为侧逆光，适合剪影"这类判断，直接喂给 P3/P4 文案；
2. **评分公式 v2**：云量分层（中高云 30–60% 加分、低云满盖减分）、湿度、能见度、太阳高度角衰减曲线加权，公式写进文档技术章节——这是 30% 完成度分里"技术深度"的直接证据；
3. **光照事件**（可选加分项，时间富余再做）："18:24 阳光正好打在平安金融中心西立面"——太阳方位角 + 建筑朝向的简单几何，一条就够惊艳，不必做全城。

## 5. 数据与技术架构

### 5.1 真实数据链路（对抗"评委输任意地点"）

```
任意地点文本 → 高德地理编码 → 经纬度
   ├─ Open-Meteo / 和风天气：云量·湿度·能见度（双源互备）
   ├─ SunCalc：日落·方位角·golden/blue hour
   ├─ 评分引擎 v2 → 分数 + 峰值时间 + 文案参数
   ├─ 机位匹配：精选库（深圳）→ 命中则出精修内容
   │            未命中 → 高德 POI 搜索（观景台/公园/滨水/天台）
   │                     + 朝向筛选，自动生成粗机位（兜底不冷场）
   ├─ 高德步行路线（OSRM 兜底）
   └─ 豆包 LLM：行动文案 + 拍摄建议（预生成文案兜底）
```

关键设计：**精选库负责惊艳，自动兜底负责不死**。评委输深圳地名 → 精修机位 + 图文步导全套；输任何其它城市 → 自动链路照样出分、出机位、出路线，话术是"精选库按城市逐个上线，深圳是首个样板城市"。

### 5.2 深圳精选机位库（20–30 个，人工精修）

- 晚霞/滨海：深圳湾公园、人才公园、前海石公园、蛇口海上世界、大梅沙；
- 城市天际线：莲花山公园山顶（望市民中心）、笔架山、香蜜公园；
- 展览/创意园（扩展场景）：OCT-LOFT 华侨城创意园、深圳当代艺术与城市规划馆、海上世界文化艺术中心；
- 街区/咖啡（数据层点缀）：欢乐海岸、南头古城。

每个机位的数据 schema：`{ id, 场景类型, 名称, 精确坐标, 站位描述, 朝向角, 样张(自拍), 步导图组, 最佳时段, 焦段/构图模板, 滤镜预设组, LLM 提示词上下文 }`。

### 5.3 机位采集与版权红线
思路.md 说"从社交媒体下载一些机位"——**位置信息可以参考，样张图片绝对不能直接用**，章程明令禁止未授权素材，被发现直接违规。正确做法：用小红书/抖音/可颂检索确定机位坐标与拍法，样张和步导图**团队自己去深圳实拍**。这次实拍本身就是章程强调的"真实场景验证"，拍摄过程顺手录成素材，直接进演示视频和文档——一鱼三吃。

### 5.4 工程迁移

- 现状：单 HTML + CDN React + 浏览器内转译多个 jsx，对 48 小时迭代速度和真机性能都不利；
- 迁移到 Vite + React（组件按现有 app/scenes/subpanels/chrome/ios-frame/tweaks 的拆分基本可平移），部署 Vercel 或火山引擎（用代金券部署有生态协同的叙事价值）；
- 后端：serverless functions 聚合天气/地理编码/机位/LLM，全部带缓存与超时降级；
- LLM 选型：初赛文档写的是 Claude API，大区赛**切换为豆包**（火山引擎代金券 + 字节生态协同双重加分），接口做成可切换；
- 真机体验：手机浏览器全屏（PWA manifest + 添加到主屏），提前专项测 iOS Safari 手势冲突、滚动性能、DeviceOrientation 权限流程；
- 降级体系：Service Worker 缓存深圳数据包（现场断网可演）；`?demo=` 参数保留但重新定位为"网络故障兜底"，路演话术里主动说明"我们有降级方案"反而是加分项（章程要求准备网络异常预案）。

## 7. 路演设计（8 分钟）

按章程建议结构分配：

1. **问题（1 min）**：刷到心动的人很多，真的出门的很少——中间那段距离是不知道值不值得、去哪、站哪、怎么拍。放一个数据钩子（好晚霞一年 30 余次的稀缺性）。
2. **方案与演示（4 min，真机投屏）**：刷 feed → 心动视频 → 上滑出卡 → 评分与时间条互动 → 轻导航 → **邀请评委现场说一个深圳地点，实时出分出机位出路线**（全场记忆点）→ 机位攻略与对齐模式 → 快拍预设 → 发布回流 feed，闭环。
3. **技术与数据（1.5 min）**：数据链路图 + 评分公式 v2 + 三层导航体系 + 降级方案，直击 30% 完成度分。
4. **商业与生态（1 min）**：抖音→追光→可颂的过渡层定位、vs 小红书/美团的时间差生态位、可挂接的变现点（可颂导流、团购、展演门票）。
5. **团队（0.5 min）**：初赛 → 大区赛的迭代路径，证明执行力。

问答预案（每题 30 秒版本提前写好背熟）：导航怎么保证有效（三层体系 + 对齐模式现场再演一次）；预设够不够（机位级预设，不是全局滤镜）；vs 小红书/美团/可颂；机位数据从哪来、怎么规模化（精选 + UGC 沉淀到可颂的飞轮）；评分准不准（公式 + 实拍验证对照）；为什么抖音需要你（时间差入口 + 内容生产飞轮）。

## 9. 风险与降级

- **评委输了机位库没有的城市** → 自动兜底链路必须任何城市可出结果；话术转为"样板城市策略"。
- **现场网络异常** → Service Worker 深圳离线包 + `?demo=` 兜底 + 手机热点备份，路演前 30 分钟实测场地网络。
- **iOS 罗盘权限被拒/不稳** → 静态罗盘 + 纯样张叠加降级，功能仍成立。
- **豆包 API 延迟或配额问题** → 结果缓存 + 预生成文案无缝切换（初赛已验证预生成文案质量可控）。
- **48h 现场加功能的诱惑** → 7.30 上午硬性功能冻结，新想法只进"总决赛 backlog"。
- **素材版权** → 全部样张/步导图自拍，BGM 用免版权曲库，演示视频里出现的第三方 UI 一律自绘仿制（初赛已是这么做的）。
