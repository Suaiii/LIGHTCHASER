## 一、这个页面是什么

抖音大区赛项目「追·光」的 P2 路线页：一张实时 3D 光影地图——真实深圳路网/建筑（OpenFreeMap 矢量瓦片，OSM 数据），Three.js 渲染近景建筑并用**真实太阳方位角/高度角**打光（SunCalc 推算），金色路线引导用户步行去看晚霞。最终要在抖音 AI 平台（douyin-ai.bytedance.net）用 vibecoding 复刻，所以**实现必须可迁移、可用文字规格描述清楚**（迁移三档预案见 `docs/page_specs.md` P2 节）。

技术架构：MapLibre GL（vendored v4.7.1）+ Three.js r128（vendored）通过 CustomLayerInterface **共享同一个 WebGL 上下文**——两台渲染器逐帧交替使用一个 GL 上下文，绝大多数疑难杂症都源于此。

## 二、核心未解决问题（接手人从这里开始）

**症状：3D 建筑群"有时候"整体消失**（用户真机反复复现，措辞演进："有时连 3D 模型都刷没了" → "拉远、旋转一多还是会消失" → 三轮修复后 **"还是老问题"**）。

已排除/已修的消失原因（v4.4–v4.6，见第五节），自动化测试全绿，但**用户真机仍复现**。说明还有至少一个未定位的根因，且它在 Playwright headless（软件渲染、8fps）环境里不复现。

### 首要排查方向（按嫌疑排序）

1. **WebGL context lost（头号嫌疑，当前代码完全没有处理）**。
   真机 GPU 内存压力/驱动重置会触发上下文丢失。MapLibre 自带恢复机制（地图会自己回来），但我们的 Three renderer 持有旧上下文的全部资源（几何/纹理/阴影贴图/PMREM envMap），恢复后 Three 层**静默失效**——表现恰好是"地图还在、3D 楼没了、刷新页面就好"。
   排查：真机 DevTools console 监听 `webglcontextlost/webglcontextrestored`；复现时看是否成对出现。
   修法方向：监听 restore 事件后销毁重建整个 Three 层（`map.removeLayer` + 重新 `addLayer` + 重新 `setBuildings`）。

2. **真实手势 vs 测试手势的时序差**。自动化测试用 `jumpTo`（离散跳变），用户用的是连续手势+惯性（触摸板捏合/双指旋转）。惯性动画期间 `isMoving()` 长时间为 true，`recheck` 会不断顺延（每次 +900ms）；若手势足够频繁，补建可能被无限饿死。排查：真机连续操作 1-2 分钟后看左上角 HUD 栋数是否还更新。

3. **系统代理导致瓦片长时间不齐**。用户本机走 127.0.0.1:7897 代理，OpenFreeMap 瓦片可能间歇性慢/失败。瓦片不齐 → `pendingMove` 挂起 → 若 `sourcedata(isSourceLoaded)` 因请求失败永不触发，楼停在旧位置（视口内=空）。排查：DevTools Network 看 tiles.openfreemap.org 是否有长时间 pending/失败。

4. **grow 状态机卡死**。生长动画（v4.6）若在某个真实序列下 `growTarget=0` 后没有信号再拉回 1（例如 zoom 事件在某种手势下不触发 syncLod），楼永久缩在地里。排查：复现时 console 输入 `window.__zgGrow`（0=缩没，1=满高）和 `window.__zgMap.getZoom()`，若 zoom≥13.8 而 __zgGrow=0 即中此坑。

### 复现时的取证清单（5 分钟）
- 左侧提示行构建号（确认不是缓存旧版）
- console：`window.__zgGrow`、`window.__zgB`（最近一次换装的栋数/顶点数）、`window.__zgMap.getZoom()`
- console 有无红错 / `webglcontextlost`
- Network 面板 openfreemap 瓦片状态
- 录屏（操作过程 + 消失瞬间）

## 三、用户需求红线（验收标准，历轮反馈原意汇总）

**数据真实性（最高优先级，F6 红线）**
1. 建筑/道路必须是**当前视口的真实数据**（矢量瓦片实时查询），不允许本地 mock、不允许随机生成——"最后的呈现一定不能是这样子的"。
2. 光照时刻控制量必须**基于可获得的数据推断**（SunCalc 真实太阳几何），不允许凭空编造。

**稳定性（用户容忍度为零的部分）**
3. 任何操作（旋转/俯仰/缩放/平移，任意组合、任意时长）下建筑**不消失**——当前未完全达标，见第二节。
4. 不抖动、无残影、无乱码、无闪烁条纹（已达标，勿退化——修复机制见第五节）。
5. 不卡顿——重建不掉帧、交互丝滑。

**视觉（用户逐轮调出来的定调）**
6. 日落感 = 低照度高对比：暗蓝基底，只有受光面染日落色；**楼是配角不能抢戏**（太亮=不合格）。
7. 建筑**半透明**（当前 opacity 0.68），透出底下路网；金属反光质感（metalness+envMap）。
8. 一栋楼必须有受光面/背光面之分；楼间有投影落在路面。
9. 地标文字不被挤压、不与楼穿插堆叠。
10. **生长动画**：放大到有建筑数据的层级（z≥13.8）楼从地面生长出来，缩小则缩回地里；由 zoom 控制、跟数据源走；动画连续、中途反转不跳变（v4.6 已实现，验收时重点测阈值附近来回缩放）。

**工程**
11. 代码轻量、无死代码（"屎山该删要删"）。
12. 改 UI 必须保留 1.0（`public/legacy-v1/` + release tag `lightchaser-v1.0`）。
13. 手机端适配；最终可迁移到抖音 AI 平台。

## 五、已修复机制清单（防退化——动这些代码前先懂为什么）

共享 WebGL 上下文的六类帧间不稳定源，全部实测踩过：

1. **GL 状态污染**：Three render 前必须 `renderer.resetState()`（旧 `state.reset()` 不完整→随机乱码残影）；PMREM 生成后也要补一次。
2. **同位面 z-fight**：剪影 fill-extrusion 层与 Three 楼是同一批建筑、面完全重合——两者绝不能同时不透明可见（现由 LOD 交叉淡化管理）。
3. **阴影抖动**：`shadowMap.autoUpdate=false`，只在换装/满高时 `needsUpdate=true` 烘一次。
4. **掠射角 shadow acne**：日落 7° 低角度下无法调参根治→立面 `receiveShadow=false`，明暗交给 N·L，楼影保留在地面 ShadowMaterial。
5. **视锥误剔除**：MapLibre 裸相机无正确视锥→合批 mesh `frustumCulled=false`（曾致特定角度整片消失）。
6. **瓦片是异步流**：任何时刻 `querySourceFeatures` 都可能只拿到部分楼（曾 136/1100 栋永久定格）。规则：`sourcedata(isSourceLoaded)`=到齐信号触发补建；**只有建成才记账**（失败保留旧楼）；换装先建后拆；近距移动未齐不换（pendingMove），远跳(>2km)残缺也比空场强。

性能红线：r128 ExtrudeGeometry 本就非索引，勿调 `toNonIndexed()`（每栋一条 console.warn）；几何分帧构建 ≤80 栋/帧；pulse `setData` 隔帧；render() 复用 Matrix4。

其他工程细节：分帧构建完成时组件可能已重挂——操作 map 前判 `map.style` 存在（死 map 上调 style API 会炸）；`buildToken` 作废过期构建；HUD 构建号必须递增。

## 七、关键参数速查（调参口）

| 参数 | 位置（搜索关键字） | 当前值 | 含义 |
|---|---|---|---|
| LOD_Z | `const LOD_Z` | 13.8 | 光影楼/剪影层切换 zoom 阈值 |
| 生长/缩回时长 | `dur = growTarget > growFrom ? 750 : 480` | 750/480ms | 生长动画 |
| 楼透明度 | `opacity: 0.68` | 0.68 | 用户要求"有一定透明度" |
| 主光强度 | `DirectionalLight(..., 0.95)` | 0.95 | 再亮就抢戏 |
| 楼影浓度 | `0.3 * e` 与 ShadowMaterial | 0.3 | 随生长淡入 |
| 重建门槛 | `< 400 && ... < 0.5` | 400m / 0.5z | 小拖动不重算 |
| 远跳阈值 | `> 2000` | 2km | 超过则允许残缺换装 |
| 合批上限 | `slice(0, 1100)` | 1100 栋 | 性能上限 |
| 分帧粒度 | `idx + 80` | 80 栋/帧 | ≈16ms 帧预算 |
